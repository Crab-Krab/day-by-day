Bug fixes for routine editing, saved-data recovery, and accessibility.

## Download and update

1. **Back up your tasks before updating.**
2. Under **Assets**, download **Day-by-Day.html**. **Read-me.txt** contains usage instructions.
3. Replace your working HTML and open it in the same browser and file location. Restore your exported backup if needed.

The app remains a self-contained HTML file that works locally without an installation, account, server, or internet connection. Saved data remains format 5, compatible with v1.2.0. Older format-1 through format-5 backups can still be imported; HTML versions older than v1.2.0 cannot read format 5.

## Fixes

- **Routine edit dates:** Editing from Weekly routines defaults to today instead of the last browsed future date. Editing from a future calendar day still defaults to that selected day.
- **Routine-edit Undo:** Restore the complete previous routine definition, including later scheduled changes that saving replaced, with the existing Undo action.
- **Recovery after a failed load:** Download the original saved text unchanged from the warning. Backup no longer exports an empty fallback session as if it contained the original tasks. Unsaved-session exports are clearly separated. Failed restores preserve the recovery copy, and restoring warns before replacing unreadable data.
- **Accessible task controls:** Completion-toggle labels include the occurrence date and remain stable when completion changes. Repeated status messages can be announced again. Move to today opens today's view and focuses the moved task. Focus restoration avoids hidden checklist controls in the routine catalog.
- **Regression coverage:** Add checks for recovery, restore failures, routine-edit defaults and Undo, repeated announcements, dated labels, and visible focus after moving tasks.

The existing Overdue rules, Monday-first calendar, and reminder behavior are unchanged.

## Validation

JavaScript syntax, standalone packaging, and the automated scheduling, runtime, theme, and history/migration suites passed. These checks do not verify actual local-file visual behavior in every browser; the earlier intermittent Edge checklist click/focus issue remains unconfirmed long term.
