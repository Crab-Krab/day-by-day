A small follow-up to v1.6.2: **Create new task file** now explains what to do when no folder was chosen.

## What's fixed

- **No more silent dead end.** Chrome doesn't allow Documents, Desktop, Downloads or your user folder themselves as a task-file folder, even when Documents and Desktop are stored in OneDrive. Before, picking one of them, or clicking **Don't Allow**, left the app looking unchanged. Now the panel says **No folder chosen** and suggests making a folder inside one, such as `Documents\Day by Day`, and choosing that.

Chrome reports a refused folder, **Don't Allow**, and Cancel to the app the same way, so the same hint appears for all three.

## Download and update

Back up tasks and wait for any file save to finish, then close the old app tab. Download **Day-by-Day.html** from Assets, replace your working HTML, and reopen it in the same browser and location. Your connected task file keeps working.

The app is still one self-contained HTML file with nothing to install, and the browser enforces that it never connects to the internet. Saved-data format remains 5, so v1.4.x through v1.6.3 can read each other's tasks and backups.

## Validation

All automated suites passed, and GitHub runs them on Node 22 and 24. The interface browser tests passed in Chrome and Edge, and the release workflow ran the Chrome browser checks before publishing. Which folders Chrome allows was checked by hand in Chrome 157 on Windows 11, and the results are in `docs/TESTING.md`.
