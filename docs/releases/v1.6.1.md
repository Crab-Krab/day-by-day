A data-safety update from two independent audits: fewer needless prompts when reconnecting your task file, safer file setup, sturdier recovery copies, and tabs that ask instead of overwriting each other. The layout is unchanged.

## Task file autosave

- **Reconnect asks only when it has to.** After the browser forgets file permission, **Reconnect task file** compares the file, the browser copy, and the last synced copy. If only your browser changed, your newer tasks save. If only the file changed, it loads. It asks which copy to keep only when both changed, and neither answer is highlighted, so a quick click can't discard your work.
- **Create new task file.** **Set up autosave** is renamed **Create new task file**, and the panel says existing files belong in **Open task file**. The save dialog suggests a dated name, such as `Day-by-Day-tasks-2026-11-10.json`, so it never offers your existing file by default. Saving over a file in that dialog can empty it before the app reads it.
- **A wrong pick doesn't pause saving.** Choosing a file that isn't a task file in **Change file**, or cancelling the switch, keeps saving to your working file.
- **Slow startups are reported.** If the browser is slow to answer at startup, the panel says the task file couldn't be checked instead of looking like first-time setup.

## Recovery copies

- **A cleanup can't push out older copies.** Deleting many tasks or ending many routines in a row saves one copy per 5 minutes, from before the first one. Copies before restoring or choosing which copy to keep are always saved.
- **Closing right after a change is safer.** While a copy is being written, the panel says **Saving a recovery copy…** and the browser asks before you close the page.
- **No name clashes.** Copy names include a random part, so two app windows never overwrite each other's copy. Copies with older names still appear and restore.

## Multiple tabs and messages

- **Near-simultaneous saves ask first.** If two tabs save at almost the same moment, the later one asks which copy to keep instead of erasing the earlier change. Normal use with two tabs is unchanged.
- **Edits to a task another tab changed or deleted ask first.** A deleted task can be saved as a new one, and **Cancel** keeps your draft. **Task updated.** no longer appears when nothing was saved.
- **Restore occurrence is accurate.** Skipped days the routine no longer runs on aren't offered for restoring.

## Download and update

Back up tasks and wait for any file save to finish, then close the old app tab. Download **Day-by-Day.html** from Assets, replace your working HTML, and reopen it in the same browser and location. Your connected task file keeps working. Its name doesn't change.

The app is still one self-contained HTML file with nothing to install, and it never contacts the internet. Saved-data format remains 5, so v1.4.x, v1.5.0, v1.6.0, and v1.6.1 can read each other's tasks and backups.

## Validation

All automated suites passed, and GitHub runs them on Node 22 and 24. The interface browser tests passed in Chrome and Edge at desktop and phone widths, with animations on and off, along with the earlier browser checks. Two tabs were also checked in real Chromium from the downloaded file. Real file-permission prompts, including whether saving over an existing file empties it, still need the manual checklist in `docs/TESTING.md`.
