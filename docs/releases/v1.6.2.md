A safety update: creating a task file can no longer wipe an existing one, and the browser now enforces that the app never connects to the internet. The layout is unchanged.

## Safer task file setup

- **Create new task file asks for a folder.** The app creates `Day-by-Day-tasks.json` in the folder you choose, such as a **Day by Day** folder inside Documents. If that folder already has a task file, including `Day-by-Day-data.json` from older versions, the app opens it instead of replacing it, and asks which tasks to keep if they differ.
- **Why it changed.** A manual test in Chrome 157 on Windows 11 confirmed that choosing an existing file in a Save dialog and confirming Replace empties it before the app can read it. Earlier versions used a Save dialog for this button. This version never does.

Already connected to a task file? Nothing changes for you. **Open task file** works as before for a file kept anywhere else.

## Privacy enforced by the browser

- **Content Security Policy.** The HTML now tells the browser to run only the app's own built-in code and to block every connection. "Never contacts the internet" is a rule the browser enforces, and anyone can see it at the top of the file.
- **Local files share storage.** In Chrome and Edge, every HTML file you open from your own computer shares the same browser storage. Only open local HTML files you trust. A connected task file is not affected.

## Download and update

Back up tasks and wait for any file save to finish, then close the old app tab. Download **Day-by-Day.html** from Assets, replace your working HTML, and reopen it in the same browser and location. Your connected task file keeps working.

The app is still one self-contained HTML file with nothing to install. Saved-data format remains 5, so v1.4.x through v1.6.2 can read each other's tasks and backups.

## Validation

All automated suites passed, and GitHub runs them on Node 22 and 24. The interface browser tests passed in Chrome and Edge at desktop and phone widths, with animations on and off, along with the earlier browser checks. A new browser test opens the downloaded file from disk and confirms the page policy refuses outside code and connections. The release workflow now runs the Chrome browser checks itself before publishing. Real folder-permission prompts still need the manual checklist in `docs/TESTING.md`.
